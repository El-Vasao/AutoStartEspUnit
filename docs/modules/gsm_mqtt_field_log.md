# Полевой лист GSM / MQTT

Рабочий лист оператора для [`gsm.md`](gsm.md) § «Сценарии проверки» **4–7**.
Прошивка этот прогон не заменяет — заполнять на устройстве после прошивки.

| # | Сценарий | Пройден? | Дата | Заметки / фрагменты журнала |
|---|----------|----------|------|------------------------------|
| 4 | Уход из READY / передача переподключения | ☐ | | Ожидание: `[Sim800TcpTransport] вызов stop()` / CIPCLOSE до SAPBR; `[CellularCore] GSM вышел из READY — слив MQTT`; пауза растёт при повторных сбоях; сбрасывается после устойчивого Connected |
| 5 | Доставка `diag.last_err` | ☐ | | Ожидание: status несёт `diag.last_err` после отключения; обрыв TCP посреди SEND → `last_err` снова после переподключения (не съеден ранним markDelivered) |
| 6 | Шлюз подтверждения команды | ☐ | | Ctrl занят: нет исполнения без 202 (`команда не в очереди (ack занят)`); живая сессия: `run` → 202, затем 200/500 |
| 7 | Потолок поиска скорости | ☐ | | Неверная скорость или молчащий модем: после `BAUD_SEARCH_MAX_PASSES` → ERROR и `GSM_NO_RESPONSE`, не бесконечный поиск |
| 8 | CALL_OWNER | ☐ | | Задать `owner_phone`; выполнить программу с CALL_OWNER. Ожидание: `[CellularCore] слив MQTT для эпохи голос/SMS`; `ATD…;`; сброс; MQTT переподключается после эпохи |
| 9 | SMS_OWNER | ☐ | | SMS_OWNER с текстом ASCII `message`. Ожидание: приглашение `CMGS`, Ctrl+Z, OK; SMS дошло на телефон |
| 10 | Входящий DTMF | ☐ | | Звонок от владельца; ввести `dtmf_password`, затем цифры id программы и `#`. Форматы CLIP `+7` и `8`; чужой CLIP игнорируется; MQTT возобновляется после ATH |

Заново проверить дым **1–3** (приём HTTP, рукопожатие MQTT и `публ. online` только после SUBACK, UI SoftAP и SSE `gsmState`/`csq`/`mqttConnected`), когда проверяется кандидат на выпуск.
