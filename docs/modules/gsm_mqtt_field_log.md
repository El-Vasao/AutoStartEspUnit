# Полевой лист GSM / MQTT

Пустой стендовый чеклист. Поведение задаёт [`gsm.md`](gsm.md). Этот файл не норма и не запись прошлых прогонов.

Рабочий лист для [`gsm.md`](gsm.md) § «Сценарии проверки» **4–7**.
Прошивка этот прогон не заменяет — заполнять на устройстве после прошивки.

| # | Сценарий | Пройден? | Дата | Заметки / фрагменты журнала |
|---|----------|----------|------|------------------------------|
| 4 | Уход из READY / передача переподключения | ☐ | | Ожидание: CIPCLOSE до SAPBR; `GSM left READY — flushing MQTT`; `reconnect (…) pause=%us`; пауза сбрасывается после устойчивого Connected |
| 5 | Доставка `err` | ☐ | | Ожидание: status несёт ключ `err` после отключения; обрыв TCP посреди SEND → `err` снова после переподключения (не съеден ранним markDelivered) |
| 6 | Шлюз подтверждения команды | ☐ | | Ctrl занят: нет исполнения без 202 (`command not queued (ack busy)`); живая сессия: `run` → 202, затем 200/500 |
| 7 | Потолок поиска скорости | ☐ | | Неверная скорость или молчащий модем: после `BAUD_SEARCH_MAX_PASSES` → ERROR и `GSM_NO_RESPONSE`, не бесконечный поиск |
| 8 | CALL_OWNER | ☐ | | Задать `owner_phone`; выполнить программу с CALL_OWNER. Ожидание: `MQTT flush for voice/SMS epoch`; `ATD…;`; сброс; MQTT переподключается после эпохи |
| 9 | SMS_OWNER | ☐ | | SMS_OWNER с текстом ASCII `message`. Ожидание: приглашение `CMGS`, Ctrl+Z, OK; SMS дошло на телефон |
| 10 | Входящий DTMF | ☐ | | Звонок от владельца; ввести `dtmf_password`, затем цифры id программы и `#`. Форматы CLIP `+7` и `8`; чужой CLIP игнорируется; MQTT возобновляется после ATH |

Заново проверить дым **1–3** (приём `+IPD` после `CIPRXGET=0`, рукопожатие MQTT: `pub state full`, затем `pub online true` после SUBACK, UI SoftAP и SSE `gsmState`/`csq`/`mqttConnected`), когда проверяется кандидат на выпуск.
